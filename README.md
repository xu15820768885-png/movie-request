# 映单

一个私人影视请求系统：成员通过 TMDB 搜索并提交准确的电影或剧集，管理员手动处理资源、更新状态并留下回复。新请求会通过 Telegram 通知管理员。

## 主要功能

- 管理员和家人独立账号
- TMDB 中文搜索、海报、年份、类型和唯一 ID
- 服务端二次查询 TMDB，无法凭空提交未收录影片
- 待处理、已收到、寻找中、已完成和暂时无法完成
- 管理员文字回复
- Telegram 新需求和状态更新通知
- Telegram 菜单查看“求片需求”和“完成情况”
- Emby API 对照媒体库，已存在资源自动显示“已入库”
- 影片详情按 TMDB ID 查询癫影资源，可比较清晰度、编码、音轨和字幕
- 影巢与癫影同时查询，影巢资源优先显示且互不阻塞
- 独立“我的追更”栏目，以 Emby 已有集数作为起点
- 管理员可把选定的影巢长期更新资源绑定为原生 `media_resource` 订阅
- 识别 `S01E233`、`第233集`、`1-233集`、合集和全集
- 已有部分集数时只接收明确缺失的单集；整部未入库时允许手动确认整剧转存
- 影巢 OAuth 授权状态、加密令牌和低频订阅消息检查
- 解锁癫影返回的 115 分享并转存到管理员指定目录
- 115 扫码登录支持支付宝/微信小程序、安卓、iOS、Windows、macOS、Linux 等设备身份
- 癫影每日自动签到，可自定义时间并选择普通签到或运气签到
- 后台每 5 分钟自动同步 Emby，打开的页面每分钟刷新状态
- SQLite 数据库保存在 NAS 本地
- 手机、平板和电脑自适应界面

## 绿联 NAS 部署

将 `compose.yaml` 保存到 `/volume1/docker/movie-request`，然后在绿联 Docker 的“项目”中导入并部署。也可以在该目录运行：

默认通过 `ghcr.mirrorify.net` 加速拉取公开的 GHCR 镜像，适合国内网络；镜像内容仍来自本项目发布的 `ghcr.io/xu15820768885-png/movie-request:latest`。

Compose 默认将外部 HTTP/HTTPS 请求交给 `http://192.168.31.129:7890`，用于访问 TMDB；局域网段已加入 `NO_PROXY`，访问 NAS 和 Emby 不会绕行代理。如代理地址不同，请修改这三项环境变量。

```bash
docker compose pull
docker compose up -d
```

浏览器访问：

```text
http://NAS-IP:1802
```

数据保存在：

```text
/volume1/docker/movie-request/data
```

首次打开时创建管理员账号并填写 TMDB API Read Access Token。之后在“成员账号”中创建登录账号，在“系统设置”中配置 Telegram 和 Emby。

在管理员的“癫影与 115”页面中：

1. 填写癫影站点地址和 OpenAPI Key。
2. 选择普通签到或运气签到，设置每天执行时间并启用自动签到。
3. 选择一个不影响现有终端的 115 设备身份，然后扫码登录。
4. 浏览 115 目录并选择家人转存资源的目标文件夹。

影巢应用审核通过后，在同一配置页面填写 Client ID、App Secret、固定 Redirect URI 和云服务器固定出口代理，然后点击“连接影巢”完成一次 OAuth 授权。影巢每日签到支持普通签到、运气签到、自定义时间和手动立即签到；启用前需为应用增加 `write` 权限并重新完成 OAuth 授权。审核前不填写凭证时，影巢模块保持关闭，原有 TMDB、Emby、癫影和 115 功能不受影响。

云服务器固定出口模板位于 `deploy/hdhive-egress`。它只代理影巢 API 的小型 HTTPS 请求，不传输影片文件；NAS 原有的动态代理仍可继续用于 TMDB 等服务。

家人打开影片详情后，页面会同时按 TMDB ID 查询影巢和癫影；选中版本即可转存。如果没有资源或版本不满意，仍可点击求片交给管理员处理。电视剧详情可以加入“我的追更”，影巢优先、癫影备用。管理员可以在追更页选择一个影巢长期更新资源并开启原生订阅；订阅站内信只负责触发更新检查，最终仍经过集数识别、重复保护和 115 安全预检。
剧集资源会在版本标题旁显示季数和集数范围；每次手动或自动签到的成功/失败记录都会发送到已配置的 Telegram 机器人。

敏感信息不会写入镜像或 GitHub。OpenAPI Key、115 Cookie、目标目录 CID、账号和求片记录全部保存在 NAS 映射的 `/volume1/docker/movie-request/data` 中。115 登录是否长期有效由 115 服务端决定；Cookie 失效后在管理员页面重新扫码即可。

Emby 地址可以填写 `http://NAS-IP:8096`。建议在 Emby 后台专门创建一个供本系统使用的 API 密钥，方便以后单独撤销。

如果 Telegram 无法直连，在系统设置中填写 Mihomo HTTP 代理，例如 `http://192.168.31.129:7890`。新需求通知、机器人菜单和消息轮询都会使用该代理。

## 更新

```bash
docker compose pull
docker compose up -d
```

数据库位于 NAS 映射目录中，更新容器不会删除账号和求片记录。每次推送到 GitHub 的 `main` 分支都会自动构建并发布新的 Docker 镜像。
